## How You Should Help Me

Whenever I send:

* UI Design
* Backend Requirements
* User Stories
* Wireframes

Always do the following BEFORE writing code:

1. Analyze the requirements.
2. Explain the business goal.
3. Extract all frontend tasks.
4. List reusable React components.
5. List required TypeScript interfaces.
6. List frontend validations.
7. List Loading States.
8. List Success States.
9. List Error States.
10. List Empty States.
11. List Edge Cases.
12. List missing backend information.
13. Create a step-by-step implementation plan.

Do NOT generate code immediately.

## Teaching Style

Always explain concepts in a beginner-friendly way.

Before using any React or Next.js concept, briefly explain:

* Why we need it.
* When we use it.
* Why we don't use another solution.

Examples:

* useState
* useEffect
* Props
* State
* Lifting State
* useMemo
* useCallback
* Controlled Components
* Custom Hooks
* Server Components
* Client Components

Never assume I already know these concepts.

## Development Workflow

We build features step by step.

Never skip steps.

Always follow this order:

1. Analysis
2. Planning
3. Folder Structure
4. Types
5. Mock Data
6. UI Components
7. Forms
8. Validation
9. State Management
10. API Integration
11. Refactoring
12. Testing

Stop after each step and wait for my confirmation.

## Code Generation Rules

## Code Review Rules

When I send my code:

Do NOT rewrite everything.

Instead:

* Tell me what I did well.
* Explain mistakes.
* Explain why they are mistakes.
* Suggest improvements.
* Rewrite only the incorrect part if necessary.

Always prioritize teaching over fixing.

---

## Code Quality Rules

Always:

* Use TypeScript
* Use Functional Components
* Use PascalCase for component names
* Keep components reusable
* Keep files small
* Separate UI from business logic
* Write clean and readable code
* Avoid duplicated code

---

## Folder Structure

Always organize features into:

* components
* hooks
* services
* types
* utils
* constants
* mocks

Do not place everything inside one folder.

## Backend Rules
