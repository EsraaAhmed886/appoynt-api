# APPOYNT - Project Context

## Project Overview

Appoynt is a Graduation Project that aims to build a complete Healthcare Management System.

The platform connects patients with healthcare providers and offers an integrated system for appointment booking, medical record management, healthcare services, and administration.

The project focuses on providing an efficient digital healthcare experience for both patients and healthcare providers.

---

# Target Users

The platform supports multiple user roles.

Current roles include:

* Patient
* Doctor
* Hospital
* Laboratory
* Radiology Center
* Receptionist
* Admin
* Super Admin

Additional roles may be introduced during the planning and development phases.

---

# Platforms

The project consists of multiple applications.

## Patient Application

The patient application allows users to:

* Search healthcare providers
* View public doctor profiles
* Book appointments
* Manage appointments
* Receive notifications
* Access available healthcare services

Doctors may also access some features through the mobile application when required.

---

## Web Dashboard

The web application is designed for management purposes.

Current dashboard users include:

* Doctors
* Admins
* Super Admins
* Receptionists (future scope)

The dashboard allows users to manage healthcare services according to their permissions.

# Development Workflow

The development workflow follows this sequence:

Business Requirements

↓

Backend Requirements

↓

UI Design (Figma)

↓

Frontend Development

↓

Backend Integration

↓

Testing

The backend team defines the business logic.

The frontend implementation must follow backend requirements instead of making assumptions.

---

# Backend Integration Principles

The UI Design defines only:

* Layout
* Components
* User Experience

Business logic always comes from Backend Requirements.

Never assume:

* API endpoints
* Request payloads
* Response payloads
* Validation rules
* Business rules

If backend information is missing, identify it clearly and ask questions instead of making assumptions.

Use mock data until backend APIs become available.

---

# Coding Philosophy

The project should follow:

* Reusable Components
* Clean Architecture Principles
* Separation of Concerns
* Readable Code
* Maintainable Folder Structure
* Scalable Frontend Design

Every component should have a single responsibility whenever possible.
